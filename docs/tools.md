# Tools

What each tool does, what you can ask it, and what comes back. You never call these yourself: you ask Claude in
plain words, and Claude picks the tool. This page is here so you know what Claude can do, and so you can check an
answer.

Every tool only reads data. None of them can change anything, upload anything or see patient information.

## How results look

- **A table, then notes.** Results come back as CSV, a plain table you can paste into a spreadsheet, followed by
  lines starting with `#` that say where the numbers came from, how they were read, and what the data can't tell
  you. Claude should repeat those notes in its answer. If it doesn't, ask it to.
- **Every number is traceable.** Rows carry their `source_id` and `retrieved_at` (when the data was fetched). After
  the table, one `Provenance for …` line per source gives the publisher's web address, the fetch time, the
  fingerprint (sha256) of each raw file, the snapshot and contract version, the contract's review status
  (`contract_status: draft` until a maintainer reviews it), the licence and how to cite it. [`get_provenance`](#get_provenance) gives the exact
  files.
- **Every number is labelled.** The `measure` column says whether it is a count, rate, percent or estimate, and
  `period_status`, on every row, says how final it is (provisional, a running total so far, incomplete, or what the
  publisher marks). See [Data conventions](data-conventions.md).
- **Restricted sources are read live.** Sources whose terms don't allow anyone to host a copy (today, WHO) are
  read from the publisher when you ask, held in memory for a few minutes and never stored. Each answer starts with
  a line saying so, with WHO's terms and how to cite it.
- **Computed numbers say so.** Rows from the analysis tools end with a `computed` column naming the method, so a
  rate or interval worked out here can't be mistaken for a published one.
- **Structured output.** Every tool also takes `fmt="json"`, which returns the same columns, rows and notes as
  structured data. Claude uses this when it needs to; you don't need to ask.

## Finding data

### `list_sources`

**What's loaded.** One row per source: who publishes it, its years and places, how often it updates, when it was
last fetched, its licence, and whether its contract has been reviewed.

| Parameter | Required | What it does |
|---|---|---|
| `condition` | no | Only sources that report this condition, e.g. "legionellosis" |
| `geography_level` | no | Only sources that go down to `nation`, `region`, `state`, `city`, `country` or `who_region` |

**Returns:** `source_id`, `title`, `publisher`, `years`, `geography`, `updated`, `last_fetched`, `licence`,
`review`. A note explains that `review = draft` means no maintainer has checked the contract yet.

**Try:** "Use health-data-registry: what data do you have on tuberculosis?"

### `search_datasets`

**Datasets that fit a topic,** ranked, each with one line on why it fits.

| Parameter | Required | What it does |
|---|---|---|
| `topic` | no | Words such as "legionella" or "syphilis in states" |
| `id_area` | no | Research area: `infectious_disease`, or `denominator` for population |
| `geography` | no | Geography level, as for `list_sources` |
| `year_start`, `year_end` | no | Only datasets that overlap these years |

**Returns:** up to five rows of `source_id`, `title`, `agency`, `years`, `geography`, `why_it_fits`. The note
suggests `describe_dataset` next.

**Try:** "Which datasets cover carbapenem resistance by state?"

### `describe_dataset`

**One dataset explained in clinical words:** what one row is, which conditions you can ask for and their case
definitions, what each column means, which rows are totals, which numbers can be added up and which can't, the
caveats, the open questions, how to cite it, its licence and review status.

| Parameter | Required | What it does |
|---|---|---|
| `source_id` | yes | The dataset, e.g. `cdc_nndss_weekly` |

**Returns:** a short plain-text description (or the same as structured data with `fmt="json"`).

**Try:** "Before we use it, describe the NNDSS weekly dataset: what can't it tell me?"

### `suggest_datasets`

**For a research question in your own words:** which sources can answer it, which can't, and why.

| Parameter | Required | What it does |
|---|---|---|
| `question` | yes | Your question, e.g. "Is congenital syphilis rising in Michigan since 2022?" |

**Returns:** one row per source with `source_id`, `can_answer` (yes or no), `why` (for example "goes down to
nation only, not state", or "covers 2011-2022 only") and `what_it_supports`. The notes say how your question was
read (condition words, places, years), and repeat that public data shows what and where, while your hospital's own
data, kept in approved systems, answers why.

**Try:** "Which public datasets could support a project on C. diff in older adults?"

## Getting numbers

### `get_series`

**Observed numbers over time** for a condition and places: one row per place and year, each with its source,
fetch time and case definition.

| Parameter | Required | What it does |
|---|---|---|
| `condition` | yes | The condition, in the source's words or a plain label, e.g. "legionellosis", "Candida auris, clinical" |
| `locations` | no | Places, e.g. `["Michigan", "Ohio", "United States"]`. Names, postal codes and FIPS codes all work. Leave empty for every place. |
| `year_start`, `year_end` | no | The years to return |
| `measure` | no | Only one kind of number: `cases`, `rate`, `percent`, `estimate` (or `population` for Census) |
| `sex` | no | Today only both sexes; no loaded source splits these series by sex |
| `source_id` | no | Only this source, when more than one reports the condition |

**Returns:** `location`, `year`, `value`, `lower`, `upper`, `period_status`, `measure`, `condition`,
`case_status`, `case_definition`, `source_id`, `retrieved_at`. Then notes: the method, the publisher's web
address, the main caveats, whether the contract is still a draft, and whether the local copy is a partial sample.
`lower` and `upper` are filled only where the publisher gives bounds; empty values are missing or suppressed, not
zeros.

**Try:** "How many clinical C. auris cases did Michigan and Ohio report each year from 2022 to 2025?" The
[README example](../README.md#example) shows the real answer.

### `get_aligned_with_gbd`

**The same observed rows, labelled with GBD's place and cause names,** plus the exact IHME GBD connector call to
run next. This tool never calls GBD and never judges the two against each other.

| Parameter | Required | What it does |
|---|---|---|
| `condition` | yes | As for `get_series` |
| `locations` | no | As for `get_series` |
| `year_start`, `year_end` | no | As for `get_series` |

**Returns:** `gbd_location_name`, `fips`, `year`, `condition`, `observed_value`, `period_status`, `measure`,
`case_status`, `source_id`, `retrieved_at`, `gbd_cause`, `gbd_pathogen`, `suggested_gbd_call`. The suggested call
is `get_multi_location_trend` (for a cause) or `get_etiology` (for a pathogen), with years capped at 2023, the last
GBD 2023 year. Notes repeat the [GBD rules](data-conventions.md#using-it-with-gbd).

**Try:** "Line up reported legionellosis in the Great Lakes states with GBD names, then run the GBD call it
suggests."

### `get_rate`

**A crude rate per 100,000** from case counts and Census population, labelled as computed here and never
age-standardised.

| Parameter | Required | What it does |
|---|---|---|
| `condition` | yes | A condition reported as case counts |
| `year` | yes | One year |
| `locations` | no | As for `get_series` |

**Returns:** `location`, `year`, `condition`, `cases`, `population`, `rate_per_100k`, `lower_95` and `upper_95`
(the exact Poisson, Garwood, interval), `period_status`, `flags` (why there is no rate, an unreliable-rate flag
from the source's own rule, or "provisional"), `case_source`, `population_source` and `computed`, and a note that
the rate is crude and must not be compared with age-standardised GBD or CDC rates.

The population is the Census Bureau's 1 July estimate (Vintage 2025) for states and the nation, 2020–2025. A count
that is suppressed, covers only part of a place (for example New York State without New York City) or has no
population gets no rate, and the `flags` column says why.

**Try:** "What was the crude rate of reported legionellosis per 100,000 in Michigan in 2024?"

## Checking numbers

### `get_provenance`

**Where a source's numbers came from:** the exact web addresses fetched, when, a fingerprint of each file, the
dataset version and contract version, the case definitions, and how to cite it.

| Parameter | Required | What it does |
|---|---|---|
| `source_id` | yes | The dataset |
| `year` | no | Adds a note that every row for that year comes from the fetches listed |

**Returns:** `source_id`, `url`, `retrieved_at`, `content_sha256`, `snapshot_id`, `contract_version`, then the
case definitions and the citation. The same `content_sha256` means the same bytes, so a mentor can confirm you used
the same data.

**Try:** "Give me the provenance and citation for the NNDSS numbers you just used."

### `list_caveats`

**What the data can't tell you:** each source's caveats, the facts not yet confirmed with the publisher, whether
the contract is still a draft, and the place traps that apply everywhere.

| Parameter | Required | What it does |
|---|---|---|
| `source_id` | no | Only this source |
| `condition` | no | Only sources that report this condition |

**Returns:** `source_id`, `kind` (`caveat`, `not yet confirmed`, `review` or `geography`), `caveat`.

**Try:** "What are the caveats for C. auris data?"

### `find_prior_work`

**CROI conference abstracts** on a condition, each with its link on CROI's site and a short excerpt. It covers
CROI only, so search PubMed too. Matches come from fixed word rules over each abstract's title and text, not from
reading it: check each one.

| Parameter | Required | What it does |
|---|---|---|
| `condition` | yes | The condition, e.g. `tuberculosis` or `PrEP` |
| `geography` | no | A country or region, e.g. `Kenya` |
| `years` | no | One year (`2023`), a range (`2020-2024`) or an open range (`2020-`, `-2019`) |
| `dataset` | no | A kind of data the work used, e.g. `surveillance` or `claims` |

**Returns:** `conference`, `year`, `abstract_number`, `title`, `session_type`, `link`, `poster_link`, `excerpt`,
`retrieved_at` (when the page was read) and `page_sha256` (the page's fingerprint), with notes on the source, its
contract version and CROI's terms. The full abstract and the poster are read on CROI's site.

**Incomplete years:** the index is built a year at a time at CROI's own pace (about 47 hours a year). Until every
abstract of a year is read, the tool names that year as not fully indexed and never says "no match" for it. With
no `years` given, it checks the five most recent meetings (2022-2026).

**Try:** "Has anyone presented on TB preventive therapy in Kenya at CROI since 2022?"

### `get_publication_outlook`

**How often presented abstracts at a conference became full papers**, one row per stage from idea to paper. It
is a base rate for all abstracts at that meeting, never a chance for your own idea. See
[publication-outlook.md](publication-outlook.md) for the method and sources.

| Parameter | Required | What it does |
|---|---|---|
| `conference` | no | e.g. `IDWeek` or `CROI`; leave it out to see every conference side by side |
| `design`, `data_sources`, `condition`, `geography` | no | Recorded but not used yet: they don't change the numbers until a model passes its calibration gate |

**Returns:** `conference`, `stage`, `step`, `status`, `outlook` (a sentence with the count, n and 95% interval),
`event`, `n`, `interval_95`, `interval_method`, `source`, `basis`, `model_version`, `calibration`. A stage with no
verified data says "unknown" and is never multiplied in. Today only IDWeek has a verified base rate.

**Try:** "How often do IDWeek abstracts become full papers?"

## Analysis tools

Each returns the number, its 95% interval, the method in one plain sentence (in the notes and the `computed`
column) and what the data can't say, and keeps the source's suppression and unreliable-rate flags. Counts are
the year's own running total at its last week with a number; a running total that stops early is never used.

### `compare_rates`

**Is it higher here than there, or now than then?** Two crude rates, their rate ratio and rate difference, each
with a 95% interval.

| Parameter | Required | What it does |
|---|---|---|
| `condition` | yes | One condition; if the words match more than one series (for example clinical and screening C. auris), it asks you to name one |
| `location` | yes | The first place |
| `year` | yes | The first year |
| `other_location` | one of these | A second place, same year |
| `other_year` | one of these | A second year, same place |

**Returns:** a row per rate, then the rate ratio and the rate difference (`what`, `estimate`, `lower_95`,
`upper_95`, `cases`, `population`, `period_status`, `flags`, `computed`). With fewer than 5 cases in a group, the
ratio uses an exact conditional interval and the difference has none. A note says if the case definition changed
between the two years.

**Try:** "Is legionellosis more common in Michigan than in Ohio in 2023?"

### `get_trend`

**Is it rising?** Annual percent change from a log-linear Poisson regression on year, with a 95% interval widened
for overdispersion.

| Parameter | Required | What it does |
|---|---|---|
| `condition` | yes | A condition reported as case counts |
| `location` | yes | One place |
| `year_start`, `year_end` | no | The years to fit; all years by default |
| `include_provisional` | no | `true` adds the year still in progress (left out by default) |
| `fit_on` | no | `"rates"` (default): cases against the Census population, and it refuses a year with no population; `"counts"`: case counts only, ignoring population change. One is never used in place of the other |

**Returns:** `location`, `condition`, `years`, `points_used`, `annual_percent_change`, `lower_95`, `upper_95`,
`fit_on`, `case_definition_from`, `left_out` (each year left out and why), `dispersion`, `source_id`, `computed`.
The fit is split where the contract records a case-definition change; the parts are never joined. At least 3
usable years are needed.

**Try:** "Is reported legionellosis rising in Michigan since 2016?"

### `age_adjust`

**Does age explain the difference?** A rate directly standardised to the 2000 US standard population (11 or 19
age groups), with the gamma (Fay–Feuer) 95% interval NCHS uses, beside the crude rate.

| Parameter | Required | What it does |
|---|---|---|
| `condition` | yes | A condition with case counts by age group |
| `location` | yes | One place |
| `year` | yes | One year |

**Returns:** `location`, `year`, `condition`, `age_adjusted_rate_per_100k`, `lower_95`, `upper_95`,
`crude_rate_per_100k`, `cases`, `population`, `standard`, `case_source`, `population_source`, `computed`. It
refuses when an age group's count is suppressed or the groups don't match the standard. Never compare it with
GBD's age-standardised rates (a different standard population). No loaded source has age-specific counts yet, so
today it says so.

**Try:** "What is the age-adjusted salmonellosis rate in Michigan in 2023?"

### `check_signal`

**Is this week unusual?** CDC's historical-limits check for notifiable diseases: the last 4 weeks' cases against
the same, preceding and following 4 weeks in each of the past 5 years.

| Parameter | Required | What it does |
|---|---|---|
| `condition` | yes | A condition with weekly counts |
| `location` | yes | One place |
| `year` | yes | The year |
| `week` | yes | The last week of the 4 compared (8 to 48, so the comparison stays inside the year) |

**Returns:** `location`, `condition`, `year`, `weeks`, `current_4_week_total`, `historical_mean`, `historical_sd`,
`ratio`, `lower_limit`, `upper_limit`, `signal` (above, below or within limits), `source_id`, `computed`. A
missing week is never counted as zero: it refuses instead. A flag means more or fewer reports than usual, not an
outbreak.

**Try:** "Were legionellosis reports in Michigan unusual in week 20 of 2024?"

## Last resort: `query_sql`

**For questions the other tools don't cover.** Claude writes one read-only database query over the loaded
sources; each table is named by its `source_id`.

| Parameter | Required | What it does |
|---|---|---|
| `sql` | yes | One `SELECT` query |

**Returns:** the table, then the query that ran, the method, one provenance line for every source the query read
(a query over two tables lists both), and each source's caveats and review status.
Results are capped at 5,000 rows.

It refuses anything but a careful read: more than one statement, anything that writes or reads files, functions
not on its allowlist, joins between tables that aren't declared, and queries that run too long. Prefer the named
tools: they apply the contract's rules for you (which rows are totals, what can be added up), and `query_sql`
leaves that to whoever writes the query.

## When a tool says no

A tool never shows a stack trace or an error code to you. It says, in plain words, what happened and what to try.
The common ones:

| What you see | What it means | What to do |
|---|---|---|
| "No loaded source reports '…'. Conditions available now: …" | The condition isn't in any loaded source, or is spelt differently | Use one of the listed names, or ask `suggest_datasets` |
| "… has no rows for: …" | That place isn't in the source (for example, a state in a source that covers EIP sites only) | Check `describe_dataset` for the places it covers |
| "None of the loaded sources split this by sex yet" | No sex breakdown in these series | Ask again without sex |
| "Rates and estimates can't be added up …" | More than one published rate matches, and rates are never combined | Choose the breakdown it names |
| "… is a running total, so it is read once per …" or "… is read at one …" | A running total asked for the wrong way | Ask by year, for one place at a time, or at one week |
| "'…' matches more than one series …" | `compare_rates` needs the same series on both sides | Use the full name of one series |
| "Population counts (Census) aren't loaded yet …" | `get_rate` has no denominator on this setup | Use `get_series`, or a published rate |
| "… could not be reached to download …" | A restricted source (WHO) is fetched from the publisher, and the publisher's site didn't answer | Try again in a few minutes |
| "The hub release … has no file …" or "… does not list …" | The hub release the server reads from is incomplete | Try again later, or [open an issue](https://github.com/jtouley/health-data-registry/issues) |
| "The CROI abstract index isn't loaded on this server yet …" | `find_prior_work` has no index on this server | Search PubMed and CROI's own abstract search |
| "No match for '…' among the abstracts indexed so far. The CROI index is not complete for …" | Some of the years asked for aren't fully indexed, so a missing match there means nothing | Search CROI's own abstract site and PubMed for those years |
| "'…' isn't a year or a range of years …" or "'…' runs backwards …" | `years` couldn't be read | Give one year (`2023`) or a range (`2020-2024`) |
| "The open data hub … has no published release yet" | The hub's first data release isn't out | Try again later; nothing was guessed |
| "This setup has reading data turned off for …" | This installation reads neither the hub (`HDR_HUB=off`) nor the publisher live (`HDR_FETCH_AT_RUN_TIME=0`), and has no local copy | Run the [Something's wrong](helpers.md#somethings-wrong) helper; whoever installed it removes whichever of the two settings is there |
| "That query can't run: …" | `query_sql` refused the query | Use `get_series` or `describe_dataset` instead |
| "The data for this question couldn't be read, so no numbers are shown" | Anything unexpected | Try again; if it keeps happening, run the [Something's wrong](helpers.md#somethings-wrong) helper |

## Helpers

Helpers are ready-made starters for each step from setup to pitch. They appear in Claude's menu once the connector
is added; if your Claude app doesn't show them, copy them from the [helpers page](helpers.md).

| Helper (Claude Code skill) | What it does for you |
|---|---|
| `start_here` (`/start-here`) | Tests each connected research tool and says in plain words which work and which are missing |
| `research_story` (`/research-story`) | The entry point for a research project: asks whether you already have an area or want one found, then routes you through the steps below |
| `scope_an_area` (`/scope-an-area`) | Takes an area or question in your own words and returns the datasets that fit, what each can't answer, and the questions worth refining |
| `find_opportunities` (`/find-opportunities`) | For a fellow without an area yet, looks for signals in the public data worth a study and returns a short opportunity brief |
| `refine_hypothesis` (`/refine-hypothesis`) | States the hypothesis, checks the data and whether it's new, names the confounders and what the data can't say, and revises until it's test-ready, needs revising, or should be dropped |
| `build_story` (`/build-story`), "Write my pitch or abstract" | Turns a refined hypothesis into a one-page pitch, an IDWeek abstract or a poster outline; for a case report, writes only the population-context paragraph |
| `help_me_fix_it` (`/help-me-fix-it`) | Asks what you see, matches it to known problems, and gives the fix one step at a time |
| `walk_me_through_install` | Step-by-step help installing a tool in the Claude Desktop app, including this one; never asks for a password |
| `set_up_my_project` | Writes the Project instructions to paste, with the guardrails, and says where to paste them |
